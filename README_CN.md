# Salience Ledger

Salience Ledger 是面向长期 AI 任务的确定性、来源优先记忆控制层。它由内部系统 EvoS
演进而来，解决的不是“能否搜到旧对话”，而是上下文压缩后，代理会不会忘掉真正支配
工作的用户规则、永久否决、反例、阻塞项和当前任务。

核心原则：原始事件只追加；摘要没有权威性；重点记忆固定进入恢复上下文；冲突未解决
时拒绝构建；永久否决不能被工程提案偷偷复活；仍有阻塞或反例回归未通过时不能宣称完成。

当用户前后两次语义存在歧义时，系统必须同时展示两次原话和来源并请求确认；禁止默认
采用最新说法，因为用户也可能忘记先前决定。只有新的 `user_confirmation` 事件才能完成
显式消歧。

无损迁移将旧系统的不可变 SQLite generation、构建清单、任务状态、线程记忆、来源文件
以及每一条数据库记录先完整冻结。证据一致、语义一致和允许切换是三道不同的门；语义
复审完成前，旧系统继续作为权威，新系统只做影子读取。

详细用法见 [英文说明](README.md)、[架构说明](docs/architecture.md) 和
[迁移说明](docs/migration.md)。
Codex 接入应遵循[分阶段接入合同](docs/codex-integration.md)，在复审和切换检查通过前保留
旧系统权威。
